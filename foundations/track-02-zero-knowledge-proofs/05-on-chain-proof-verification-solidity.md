# On-Chain Proof Verification in Solidity: Gas Costs and Optimization

**Track:** Intermediate → Expert  
**Read time:** 11 min

---

## The Problem

You've generated a ZK proof off-chain. Now you need to verify it on-chain. The auto-generated Solidity verifier from snarkjs works, but it costs 200,000-300,000 gas per verification. For a protocol that verifies thousands of proofs per day, that's significant. And if you're using STARKs, verification can cost millions of gas.

This blog covers how on-chain verification works, what drives the gas cost, and how to optimize it.

---

## Core Concepts

### What the Verifier Contract Does

The verifier contract performs elliptic curve operations to check that a proof is valid. For Groth16, this involves:

1. **Pairing checks**: expensive elliptic curve operations on the BN128 curve
2. **Scalar multiplications**: multiply curve points by scalars
3. **Point additions**: add curve points together

The EVM has precompiles for BN128 operations (EIP-197):
- `ecAdd` (0x06): ~150 gas
- `ecMul` (0x07): ~6,000 gas
- `ecPairing` (0x08): ~45,000 gas + 34,000 per pair

A Groth16 verification requires 3 pairing operations: ~45,000 + 3×34,000 = ~147,000 gas, plus scalar multiplications for each public input (~6,000 gas each).

### The Auto-Generated Verifier

snarkjs generates a Solidity verifier that looks like this:

```solidity
// Auto-generated by snarkjs — do not modify
contract Groth16Verifier {
    // Verification key (hardcoded from your zkey)
    uint256 constant alphax = 0x...;
    uint256 constant alphay = 0x...;
    // ... many more constants

    function verifyProof(
        uint[2] calldata _pA,
        uint[2][2] calldata _pB,
        uint[2] calldata _pC,
        uint[N] calldata _pubSignals
    ) public view returns (bool) {
        // Elliptic curve operations using precompiles
        // Returns true if proof is valid
    }
}
```

The verification key is hardcoded as constants — this is gas-efficient (constants are in bytecode, not storage).

### Gas Cost Breakdown

For a Groth16 proof with 2 public inputs:
```
ecPairing (3 pairs): ~147,000 gas
ecMul (2 public inputs × 2): ~24,000 gas
ecAdd (accumulation): ~1,500 gas
Function overhead: ~3,000 gas
Total: ~175,000 gas

At 30 gwei, $3,000 ETH: ~$15.75 per verification
```

For PLONK with 2 public inputs:
```
More pairing operations: ~250,000 gas
Total: ~280,000 gas
```

For STARKs (without recursion):
```
Hash-based verification: ~1,000,000-5,000,000 gas
Impractical for direct on-chain verification
```

### Optimization Strategies

**1. Minimize public inputs**  
Each public input adds ~6,000 gas (one ecMul). Combine multiple values into one using hashing:

```solidity
// Instead of 5 public inputs:
verifyProof(proof, [a, b, c, d, e])

// Hash them into one:
bytes32 hash = keccak256(abi.encodePacked(a, b, c, d, e));
verifyProof(proof, [uint256(hash)])
// Saves ~24,000 gas
```

**2. Batch verification**  
Verify multiple proofs in one transaction using random linear combinations:

```
Instead of: verify(proof1) + verify(proof2) + verify(proof3)
Do: verify(proof1 + r*proof2 + r²*proof3) where r is random
Saves ~2/3 of verification cost for 3 proofs
```

**3. Use L2 for verification**  
On Arbitrum or Optimism, gas costs are 10-100x lower. A 200,000 gas verification costs ~$0.15 instead of $15.

**4. Recursive proofs**  
For STARKs: prove the STARK verification in a SNARK. The final on-chain verification is a cheap SNARK (~200,000 gas) instead of an expensive STARK.

## Code Walkthrough

Production verifier integration with gas optimization:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

// Auto-generated verifier (from snarkjs)
interface IGroth16Verifier {
    function verifyProof(
        uint[2] calldata pA,
        uint[2][2] calldata pB,
        uint[2] calldata pC,
        uint[2] calldata pubSignals
    ) external view returns (bool);
}

/**
 * @title AgeGate
 * @notice Uses ZK proof to verify age without revealing it.
 * Demonstrates: proof verification, commitment scheme, nullifier pattern.
 */
contract AgeGate {
    IGroth16Verifier public immutable verifier;

    // User commitments: hash(age, salt) stored when user registers
    mapping(address => bytes32) public commitments;

    // Nullifiers: prevent proof reuse
    // A nullifier is a unique value derived from the proof that can only be used once
    mapping(bytes32 => bool) public usedNullifiers;

    uint256 public constant MIN_AGE = 18;

    event CommitmentRegistered(address indexed user, bytes32 commitment);
    event AgeVerified(address indexed user, uint256 minAge);

    constructor(address _verifier) {
        verifier = IGroth16Verifier(_verifier);
    }

    /**
     * @notice Register an age commitment on-chain.
     * @dev User computes commitment = Poseidon(age, salt) off-chain
     *      and registers it here. The commitment is public; age and salt are private.
     */
    function registerCommitment(bytes32 commitment) external {
        require(commitments[msg.sender] == bytes32(0), "Already registered");
        commitments[msg.sender] = commitment;
        emit CommitmentRegistered(msg.sender, commitment);
    }

    /**
     * @notice Verify age using ZK proof.
     * @dev Proves: age >= MIN_AGE AND hash(age, salt) == commitment
     *
     * Public signals layout (must match circuit):
     *   pubSignals[0] = minAge (18)
     *   pubSignals[1] = commitment (user's registered commitment)
     *
     * @param nullifier Unique value to prevent proof reuse
     */
    function verifyAge(
        uint[2] calldata pA,
        uint[2][2] calldata pB,
        uint[2] calldata pC,
        bytes32 nullifier
    ) external {
        // Check nullifier hasn't been used
        require(!usedNullifiers[nullifier], "Proof already used");

        // Get user's commitment
        bytes32 commitment = commitments[msg.sender];
        require(commitment != bytes32(0), "No commitment registered");

        // Build public signals
        uint[2] memory pubSignals = [
            MIN_AGE,
            uint256(commitment)
        ];

        // Verify the proof
        require(
            verifier.verifyProof(pA, pB, pC, pubSignals),
            "Invalid proof"
        );

        // Mark nullifier as used (prevent replay)
        usedNullifiers[nullifier] = true;

        emit AgeVerified(msg.sender, MIN_AGE);
    }

    /**
     * @notice Batch verify multiple proofs (gas optimization).
     * @dev Each proof is independent — verify all in one transaction.
     *      Saves base transaction cost (21,000 gas) per additional proof.
     */
    function batchVerifyAge(
        address[] calldata users,
        uint[2][] calldata pAs,
        uint[2][2][] calldata pBs,
        uint[2][] calldata pCs,
        bytes32[] calldata nullifiers
    ) external {
        require(
            users.length == pAs.length &&
            users.length == pBs.length &&
            users.length == pCs.length &&
            users.length == nullifiers.length,
            "Length mismatch"
        );

        for (uint256 i = 0; i < users.length; i++) {
            address user = users[i];
            bytes32 nullifier = nullifiers[i];

            require(!usedNullifiers[nullifier], "Proof already used");

            bytes32 commitment = commitments[user];
            require(commitment != bytes32(0), "No commitment");

            uint[2] memory pubSignals = [MIN_AGE, uint256(commitment)];

            require(
                verifier.verifyProof(pAs[i], pBs[i], pCs[i], pubSignals),
                "Invalid proof"
            );

            usedNullifiers[nullifier] = true;
            emit AgeVerified(user, MIN_AGE);
        }
    }
}
```

TypeScript: formatting proof for Solidity and estimating gas:

```typescript
import * as snarkjs from "snarkjs";
import { ethers } from "ethers";

interface SolidityProof {
  pA: [string, string];
  pB: [[string, string], [string, string]];
  pC: [string, string];
  pubSignals: string[];
}

async function formatProofForSolidity(
  proof: snarkjs.Groth16Proof,
  publicSignals: string[]
): Promise<SolidityProof> {
  // snarkjs proof format → Solidity format
  return {
    pA: [proof.pi_a[0], proof.pi_a[1]],
    pB: [
      [proof.pi_b[0][1], proof.pi_b[0][0]], // Note: B is transposed
      [proof.pi_b[1][1], proof.pi_b[1][0]],
    ],
    pC: [proof.pi_c[0], proof.pi_c[1]],
    pubSignals: publicSignals,
  };
}

async function estimateVerificationGas(
  verifierAddress: string,
  proof: SolidityProof,
  provider: ethers.Provider
): Promise<bigint> {
  const VERIFIER_ABI = [
    "function verifyProof(uint[2] pA, uint[2][2] pB, uint[2] pC, uint[2] pubSignals) view returns (bool)",
  ];

  const verifier = new ethers.Contract(verifierAddress, VERIFIER_ABI, provider);

  const gasEstimate = await verifier.verifyProof.estimateGas(
    proof.pA,
    proof.pB,
    proof.pC,
    proof.pubSignals
  );

  console.log("Estimated gas:", gasEstimate.toString());
  return gasEstimate;
}

async function submitProof(
  ageGateAddress: string,
  proof: SolidityProof,
  nullifier: string,
  signer: ethers.Signer
) {
  const AGE_GATE_ABI = [
    "function verifyAge(uint[2] pA, uint[2][2] pB, uint[2] pC, bytes32 nullifier) external",
  ];

  const ageGate = new ethers.Contract(ageGateAddress, AGE_GATE_ABI, signer);

  const tx = await ageGate.verifyAge(
    proof.pA,
    proof.pB,
    proof.pC,
    nullifier,
    {
      gasLimit: 300_000, // set explicit limit for ZK verification
    }
  );

  const receipt = await tx.wait();
  console.log("Gas used:", receipt.gasUsed.toString());
  return receipt;
}
```

## Common Mistakes and Gotchas

**1. Not handling the B matrix transposition**  
The `pi_b` field in snarkjs proof output is in a different order than what Solidity expects. The inner arrays must be reversed: `[proof.pi_b[0][1], proof.pi_b[0][0]]`. This is a silent bug — the transaction will fail with "invalid proof" if you get it wrong.

**2. Using `view` instead of `pure` for the verifier**  
The auto-generated verifier uses `view` because it reads constants. But constants are in bytecode, not storage — it could be `pure`. This doesn't affect gas significantly but is worth knowing.

**3. Not setting a gas limit for verification transactions**  
ZK verification uses a predictable amount of gas, but if the proof is invalid, the transaction reverts early (using less gas). Set an explicit gas limit slightly above the expected verification cost to avoid overpaying on reverts.

**4. Forgetting the nullifier pattern**  
Without nullifiers, the same proof can be submitted multiple times. A nullifier is a unique value derived from the proof (or the private inputs) that can only be used once. Always implement nullifiers for proofs that grant access or trigger actions.

**5. Deploying the verifier without testing invalid proofs**  
Test that your verifier correctly rejects invalid proofs. Try submitting a proof with wrong public signals, a modified proof, or a proof from a different circuit. All should fail.

## How This Connects to Production

Tornado Cash's on-chain verifier uses Groth16 verification — each withdrawal costs ~200,000 gas for proof verification. zkSync's rollup contract verifies PLONK proofs for batches of transactions. Polygon zkEVM verifies Plonky2 proofs on Ethereum mainnet. Worldcoin's identity protocol verifies Semaphore proofs on-chain to prevent double-voting. The verifier contract is the trust anchor of any ZK system — it's what makes the proofs meaningful on-chain.
