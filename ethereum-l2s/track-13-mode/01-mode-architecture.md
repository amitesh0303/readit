# Mode Architecture: OP Stack L2 with Sequencer Fee Sharing

**Track:** Mode Network Development
**Level:** Beginner
**Read time:** 10 min

---

## The Problem

You've heard Mode described as "another OP Stack chain" but also as something different — a DeFi-native L2 with sequencer fee sharing. You need to understand what makes Mode architecturally distinct from other OP Stack rollups like Optimism and Base. Without understanding Mode's fee-sharing model, SFS (Sequencer Fee Sharing) contract, and how it incentivizes protocol builders, you can't evaluate whether Mode is the right deployment target for your DeFi application or how to capture revenue from on-chain activity.

## Core Concepts

### What Mode Is

Mode is an optimistic rollup built on the OP Stack — the same modular framework powering Optimism and Base. What differentiates Mode is its economic model: the Sequencer Fee Sharing (SFS) system that distributes a portion of sequencer revenue back to the smart contract developers generating that activity.


### OP Stack Foundation

Mode inherits the full OP Stack architecture:

- **op-node**: Derives L2 blocks from L1 data, ensuring data availability
- **op-geth**: Modified go-ethereum executing L2 transactions with EVM equivalence
- **op-batcher**: Submits compressed transaction batches to Ethereum L1 as blobs
- **op-proposer**: Posts output roots (state commitments) to L1 for the challenge period

### Sequencer Fee Sharing (SFS)

The SFS contract is Mode's key innovation. When you register your smart contract with the SFS, you earn a share of the sequencer fees generated by transactions interacting with your contract.

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

/// @title IModeSFS
/// @notice Interface for Mode's Sequencer Fee Sharing contract
/// @dev Deployed at 0x8680CEaBcb9b56913c519c069Add6Bc3494B7020 on Mode Mainnet
interface IModeSFS {
    /// @notice Register a contract for fee sharing
    /// @param recipient Address that will receive the fee share
    /// @return tokenId The NFT token ID representing the fee share position
    function register(address recipient) external returns (uint256 tokenId);

    /// @notice Assign a contract to an existing SFS NFT
    /// @param tokenId The existing SFS NFT to assign fees to
    function assign(uint256 tokenId) external returns (uint256);

    /// @notice Withdraw accumulated fees
    /// @param tokenId The SFS NFT token ID
    /// @param recipient Address to receive the withdrawn fees
    /// @param amount Amount of fees to withdraw
    /// @return The amount actually withdrawn
    function withdraw(uint256 tokenId, address recipient, uint256 amount) external returns (uint256);

    /// @notice Get the accumulated balance for a token ID
    /// @param tokenId The SFS NFT token ID
    /// @return The accumulated fee balance
    function balances(uint256 tokenId) external view returns (uint256);
}
```

### Registering for Fee Sharing

Every contract deployed on Mode should register with the SFS to capture revenue:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import {IModeSFS} from "./IModeSFS.sol";

/// @title SFSRegisteredContract
/// @notice Example contract that registers with Mode's Sequencer Fee Sharing
contract SFSRegisteredContract {
    /// @dev Mode Mainnet SFS contract address
    address constant SFS_CONTRACT = 0x8680CEaBcb9b56913c519c069Add6Bc3494B7020;

    uint256 public sfsTokenId;

    constructor(address feeRecipient) {
        // Register this contract with SFS during deployment
        // The feeRecipient receives an NFT representing the fee share
        sfsTokenId = IModeSFS(SFS_CONTRACT).register(feeRecipient);
    }
}
```

### Finality and Security Model

Mode inherits the same finality guarantees as other OP Stack chains:

| Finality Level | Time | Trust Assumption |
|---|---|---|
| Soft confirmation | ~2 seconds | Trust the Mode sequencer won't reorder |
| L1 batch posted | ~5-15 min | Data posted to Ethereum, reconstructable |
| L1 finalized | ~7 days | Challenge window passed, state is final |

The 7-day challenge window means withdrawals from Mode to Ethereum L1 take 7 days via the canonical bridge. Third-party bridges (Across, Relay) provide faster exits by fronting liquidity.

### Mode's Position in the Superchain

Mode is part of the OP Stack Superchain ecosystem alongside Optimism, Base, Zora, and others. This means:

- Shared upgrade path with OP Stack improvements
- Future cross-chain messaging via OP Stack interop
- Standardized bridge contracts and withdrawal flow
- Shared security model and fraud proof infrastructure

```typescript
import { ethers } from "ethers"; // ethers@6.9.0

// Mode network configuration
const MODE_NETWORKS = {
  mainnet: {
    chainId: 34443,
    rpc: "https://mainnet.mode.network",
    explorer: "https://explorer.mode.network",
    bridge: "https://bridge.mode.network",
    sfsContract: "0x8680CEaBcb9b56913c519c069Add6Bc3494B7020"
  },
  testnet: {
    chainId: 919,
    rpc: "https://sepolia.mode.network",
    explorer: "https://sepolia.explorer.mode.network",
    bridge: "https://bridge.mode.network",
    sfsContract: "0xBBd707815a7F7eb6897C7686274AFabd7B579Ff6"
  }
};

// Check SFS balance for a registered contract
async function checkSFSBalance(tokenId: number): Promise<string> {
  const provider = new ethers.JsonRpcProvider(MODE_NETWORKS.mainnet.rpc);
  const sfs = new ethers.Contract(
    MODE_NETWORKS.mainnet.sfsContract,
    ["function balances(uint256) view returns (uint256)"],
    provider
  );

  const balance = await sfs.balances(tokenId);
  return ethers.formatEther(balance);
}
```

## Common Pitfalls

1. **Forgetting to register with SFS** — If you deploy a contract on Mode without calling `register()` on the SFS contract, you permanently miss out on sequencer fee revenue from that contract. Always register in the constructor or immediately after deployment.

2. **Confusing Mode with a standalone chain** — Mode is an OP Stack rollup that settles on Ethereum. It's not an independent L1. Your security guarantees come from Ethereum, and the 7-day challenge window applies to all canonical withdrawals.

3. **Assuming SFS revenue is immediate** — Fee sharing accumulates over time based on actual transaction volume hitting your contract. A newly deployed contract with no users generates zero SFS revenue. The model rewards protocols that drive real usage.

4. **Using the wrong SFS contract address on testnet vs mainnet** — The SFS contract is at `0x8680CEaBcb9b56913c519c069Add6Bc3494B7020` on mainnet and `0xBBd707815a7F7eb6897C7686274AFabd7B579Ff6` on Mode Sepolia testnet. Mixing these up causes silent failures.
