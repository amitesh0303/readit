# NEAR Development Environment Setup

**Track:** NEAR Protocol Development
**Level:** Beginner
**Read time:** 8 min

---

## The Problem

You want to build on NEAR but you're staring at multiple CLI tools, wallet options, and network configurations. The old `near-cli` (JavaScript-based) is being replaced by `near-cli-rs` (Rust-based, faster, better UX). You need a working local environment with testnet access before you can deploy anything. This lesson gets you from zero to a funded testnet account with all tools configured.

---

## Core Concepts

### Installing near-cli-rs

`near-cli-rs@0.11.0` is the current recommended CLI. It replaces the legacy JavaScript-based `near-cli` with a faster, interactive Rust implementation.

```shell
# Install near-cli-rs via cargo (requires Rust toolchain)
cargo install near-cli-rs@0.11.0

# Or install via npm wrapper (no Rust required)
npm install -g near-cli-rs@0.11.0

# Verify installation
near --version
```

```
Expected output:
near-cli-rs 0.11.0
```

```shell
# On macOS, you can also use Homebrew
brew install near-cli-rs
```

The CLI uses an interactive mode by default — it prompts you through operations step by step. You can also use it non-interactively with flags for scripting.

### Creating a Testnet Account

NEAR testnet accounts are free and auto-funded with 200 NEAR on creation. No faucet needed — the testnet automatically grants tokens when you create an account.

```shell
# Create a new testnet account interactively
near account create-account fund-myself myapp.testnet '200 NEAR' autogenerate-new-keypair save-to-keychain sign-as myapp.testnet network-config testnet sign-with-keychain send
```

```
Expected output:
New account "myapp.testnet" created successfully.
Transaction ID: 7gH...
The account has been funded with 200 NEAR.
```

Alternatively, create an account via the [NEAR Testnet Wallet](https://testnet.mynearwallet.com/):
1. Visit https://testnet.mynearwallet.com/
2. Click "Create Account"
3. Choose your account name (e.g., `yourname.testnet`)
4. The account is automatically funded with 200 NEAR — no faucet required

### Network Configuration

| Network | RPC Endpoint | Explorer | Use Case |
|---------|-------------|----------|----------|
| mainnet | https://rpc.mainnet.near.org | https://nearblocks.io | Production |
| testnet | https://rpc.testnet.near.org | https://testnet.nearblocks.io | Development |

### Rust Toolchain for Contract Development

NEAR smart contracts compile to WebAssembly (Wasm). You need the Rust toolchain with the `wasm32-unknown-unknown` target:

```shell
# Install Rust (if not already installed)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Add the Wasm compilation target
rustup target add wasm32-unknown-unknown

# Verify
rustup target list --installed | grep wasm32
```

```
Expected output:
wasm32-unknown-unknown
```

```shell
# Install cargo-near for contract build tooling
cargo install cargo-near@0.6.0

# Verify
cargo near --version
```

```
Expected output:
cargo-near 0.6.0
```

### Project Scaffolding

Use `cargo-near` to create a new contract project:

```shell
# Create a new NEAR contract project
cargo near new my-contract

# Project structure:
# my-contract/
# ├── Cargo.toml
# ├── src/
# │   └── lib.rs        ← your contract code
# ├── tests/
# │   └── test_basics.rs
# └── README.md
```

```toml
# Cargo.toml generated by cargo-near
[package]
name = "my-contract"
version = "0.1.0"
edition = "2021"

[lib]
crate-type = ["cdylib"]

[dependencies]
near-sdk = "5.0.0"

[dev-dependencies]
near-sdk = { version = "5.0.0", features = ["unit-testing"] }
near-workspaces = "0.10.0"
tokio = { version = "1", features = ["full"] }
```

### Building and Deploying

```shell
# Build the contract (compiles to Wasm)
cd my-contract
cargo near build

# The compiled Wasm file is at:
# target/near/my_contract.wasm
```

```
Expected output:
   Compiling my-contract v0.1.0
    Finished release [optimized] target(s)
Contract size: 142.3 KB (target/near/my_contract.wasm)
```

```shell
# Deploy to testnet
near contract deploy myapp.testnet use-file ./target/near/my_contract.wasm without-init-call network-config testnet sign-with-keychain send
```

```
Expected output:
Contract deployed successfully to "myapp.testnet"
Transaction ID: 4xK...
```

### Sandbox Testing with near-workspaces

For integration tests, use `near-workspaces@0.10.0` which spins up a local sandbox:

```rust
// tests/test_basics.rs
use near_workspaces::{types::NearToken, Account, Contract};
use serde_json::json;

#[tokio::test]
async fn test_contract_deploy() -> Result<(), Box<dyn std::error::Error>> {
    let sandbox = near_workspaces::sandbox().await?;
    let contract_wasm = near_workspaces::compile_project("./").await?;

    let contract = sandbox.dev_deploy(&contract_wasm).await?;

    let user = sandbox.dev_create_account().await?;

    let outcome = user
        .call(contract.id(), "my_method")
        .args_json(json!({"key": "value"}))
        .deposit(NearToken::from_near(1))
        .transact()
        .await?;

    assert!(outcome.is_success());
    Ok(())
}
```

```shell
# Run integration tests
cargo test -- --nocapture
```

## Common Pitfalls

1. **Using the legacy JavaScript near-cli** — The old `near-cli` (npm package `near-cli`) is deprecated. It uses different command syntax and lacks features like interactive mode. Always use `near-cli-rs@0.11.0` which is the actively maintained replacement. If you see tutorials using `near login` or `near deploy`, those are legacy syntax.

2. **Forgetting the wasm32 target** — Without `rustup target add wasm32-unknown-unknown`, your contract won't compile. The error message (`can't find crate for 'core'`) is confusing if you don't know what's missing. Add this target before your first build.

3. **Deploying without enough NEAR for storage** — Your contract account needs NEAR to cover the storage cost of the deployed Wasm binary. A typical contract (100-300KB) needs 1-3 NEAR locked for storage. If your account balance is too low, deployment fails with `NotEnoughBalance`.

4. **Confusing account credentials location** — `near-cli-rs` stores keys in `~/.near-credentials/<network>/<account>.json`. If you switch machines or delete this directory, you lose access to your accounts. Back up your credentials or use a hardware wallet for mainnet accounts.
